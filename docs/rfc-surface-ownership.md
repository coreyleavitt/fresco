# RFC: Surface ownership — one pinned-diff core, two declared modes

**Status**: Draft (round 3 architecture review applied — S3 hardening pass)
**Author**: Corey Leavitt
**Companion to**: `docs/rfc-screen-v2.md` (the reactive Screen wrapper this extends), `docs/rfc-terminal-interaction.md` (capability detection — alt-screen support), `docs/rfc-consistency-model.md` (the compile-time-first discipline the surface typing follows), `intonaco/docs/rfc-modal-tiers.md` (the □/◇ modality this borrows)
**Targets**: fresco (terminal frontend; post-Phase-2 split, builds on Screen v2)

## Why this RFC exists

fresco's renderer (`src/fresco/render.nim`) keeps a per-row diff cache (`Renderer`) of what the terminal currently shows and emits only the rows that changed, each addressed by an **absolute** `cursorTo(row)`. That is the correct, best-in-class core — it is what ncurses (`curscr`/`doupdate`), ratatui (double-buffered `Buffer`), notcurses, tcell, and Textual all do. There is no "fast and clean" terminal rendering without a model of current screen state.

The defect is not the diff cache. It is that fresco applies a **screen-ownership model to a surface it does not own.** fresco's identity is *inline*: bottom-anchored chrome floating above live shell scrollback (the modern-CLI shape — keep the user's history, prompt at the bottom). An inline surface **scrolls underneath fresco's coordinate system**: absolute row N stops mapping to the same physical line the instant anything scrolls. The diff cache is in screen-absolute coordinates; the content lives in a moving frame. That mismatch is the whole bug class.

Two concrete failures, both manifestations of the same root:

1. **Wrap-bleed.** `render()` (`render.nim:54-55`) emits each line *verbatim* after `clearLineRight()`; `Region.set()` (`render/layout.nim:50-58`) truncates content *vertically* to `r.height` but never clips each line to `r.width`. A row wider than the terminal **wraps** onto the next physical line; the diff renderer then *skips* any unchanged row below it (its entire purpose), leaving the wrapped overflow painted as a stale fragment. Observed in the amoxtli REPL as C-source fragments (`size_t len = 0;`, `EOF`) bleeding below the status divider.

2. **Lost output / stale-on-shrink.** The inline output area is a fixed in-place window that *trims* old lines into oblivion (no terminal scrollback), and when a frame has fewer lines than the previous one, `set()` replaces `target` with a shorter seq and `render()` only iterates that seq — rows below the new content keep their old cached text.

The current recovery hatch is `invalidate()` ("drop the cache; re-emit every row"), documented for "any out-of-band emission the renderer didn't see." That the hatch is *load-bearing* — that correctness depends on fresco being the sole writer and content never wrapping — is the smell. The fix is not a bigger hammer on the diff cache. It is to **scope the diff cache to rows fresco actually owns and that never scroll,** and to give everything else to the terminal's own scroll machinery.

## Thesis

**Surface ownership is a declared, type-level property, and the two terminal-app shapes the world wants — screen-owning (alt-screen) and inline (modern-CLI) — are two configurations of a single pinned-diff renderer, not two renderers.**

The difference between them collapses to one question: *where is the top edge of the live (owned, diffed) zone, and what happens to content above it?*

```
                      live-zone top edge        content above the edge
  alt-screen          row 0 (whole screen)      nothing — fresco owns every row
  inline              row H-k (bottom band)     committed → terminal native scrollback
```

- **Alt-screen mode** = the live zone is the entire alternate screen buffer. Everything is pinned + diffed. Absolute coordinates are valid because nothing scrolls out from under you. This is *almost exactly fresco today*, missing only the alt-screen enter/leave and the horizontal clip.
- **Inline mode** = the live zone shrinks to a small bottom band fresco owns exclusively. Everything above it is **committed**: printed once through the terminal's native scroll, entering real scrollback, and *never addressed again*. The diff cache covers only the volatile band.

Alt-screen mode is inline mode with the live zone expanded to the whole screen and an empty committed zone. One diff core, shared region machinery, two construction paths.

Prior art that proves the unification (frameworks that nail *both* via one switch over a shared core): **Bubble Tea** (`tea.WithAltScreen()` flips inline↔alt-screen for the same Model/Update/View), **prompt_toolkit** (`Application(full_screen=True)` vs default render-below-the-prompt). The libraries that picked one mode (ink = inline-only; notcurses/blessed = alt-screen-only) are the ones that could not generalize. Both prior-art libraries make the split *at runtime by convention*, because Go and Python have no compile-time type system worth exploiting. fresco's compile-time-first non-negotiable says we do exploit Nim's — see "Surface typing" below.

## Surface typing (the compile-time-first shape)

The naïve encoding — a `SurfaceMode` enum field on a single mutable `Screen[S]`, plus a `RegionKind` (pinned|committed) enum field on a single `Region` — fails the compile-time-first non-negotiable. A mutable enum field means the compiler cannot tell an inline screen from an alt-screen one, so every mode-specific operation must runtime-branch and every invariant must be a runtime check. The RFC's own soundness obligation (`AltScreen ⇒ committedCount = 0`) is the tell: it wants a *structural impossibility*, not a guarded assert.

So mode is a **type**, not a value. Two distinct constructors return two distinct types. They share *no* common mutable base and — per the round-2 design review — they share *no* `concept` either. (A Nim `concept` for the widget surface is a phantom abstraction: the existing widget API in `reactive/binding.nim` takes a `Region` or a `RenderTarget`, never a screen object, so nothing actually reaches for a `screen.layout`/`screen.size` member. A concept defended a coupling that does not exist, while importing concept-resolution fragility — opaque error messages that fire at the constraint site, not the call site. Dropped.) Where a genuinely screen-agnostic API later arises, it takes the two projections explicitly as a small value object:

```nim
type
  ScreenView* = object             # flat, non-ref; passed explicitly, no concept
    layout*: Layout
    size*: Signal[(int, int)]

  InlineScreen*[S: Sink] = ref object
    layout: Layout                 # holds only pinned Regions
    log: ScrollbackLog             # the committed zone (see below)
    sink: S
    size: Signal[(int, int)]       # caller-owned; SIGWINCH writes it
    liveZoneHeight: Signal[int]    # = size.map(h => h - pinnedHeaderRows); see below

  AltScreen*[S: Sink] = ref object
    layout: Layout                 # holds only pinned Regions
    sink: S
    size: Signal[(int, int)]
    # No `log`, no `liveZoneHeight` — structurally absent.

# Primary: caller owns the size signal (the SIGWINCH handler writes it), so
# everything downstream — liveZoneHeight, bound rows — reacts. Convenience
# (h, w) overload wraps a static signal for tests.
proc newInlineScreen*[S](sink: S, size: Signal[(int, int)]): InlineScreen[S]
proc newInlineScreen*[S](sink: S, h, w: int): InlineScreen[S]   # static-size convenience
proc newAltScreen*[S](sink: S, size: Signal[(int, int)], cap: AltScreenCap): AltScreen[S]
proc newAltScreen*[S](sink: S, h, w: int, cap: AltScreenCap): AltScreen[S]
```

`liveZoneHeight` is `size.map(proc(s: (int, int)): int = max(0, s[0] - pinnedHeaderRows))`, where `pinnedHeaderRows` is the fixed pinned-region height baked at construction (the inline live band is the bottom band below any fixed chrome). It does **not** derive reactively from `Layout` — `Layout` is mutated imperatively and emits no signal — so the derivation is over `size` alone with a construction-time constant. (Design review: "derived from size + layout" was underspecified; this pins it.)

**Known limitation — fixed chrome height (round-3 design).** Baking `pinnedHeaderRows` at construction means a consumer whose chrome *changes height* (a status bar that grows from one line to two) must reconstruct the `InlineScreen` to resize the live band — there is no reactive path from a chrome-height change to `liveZoneHeight`. This is acceptable for the v0 consumer (amoxtli's REPL chrome is a fixed-height divider, `pinnedHeaderRows = 1`), so the construction-time constant ships. The general fix — `Layout` emitting a height signal so `liveZoneHeight = size.zip(layoutHeight).map(…)` — is a future-`Layout` concern filed as a post-S4 follow-on, stated here so a library consumer meets it as a documented bound, not a surprise.

`commit`/`bindScrollback`/`appendLine` exist **only** on `InlineScreen`; `enter`/`leave` exist **only** on `AltScreen`. `AltScreen[S]` has no `ScrollbackLog` field, so a committed region in alt-screen is not "rejected at runtime" — it cannot be written. The invariant `AltScreen ⇒ committedCount = 0` is discharged *by construction*, with no extension to the `{.height: N.}` composer required. (The composer solves a different problem — baking reactive heights — and adapting it to layout-mode checking would be substantial new work the depth review correctly flagged. Distinct types sidestep it entirely.)

The committed zone is a **separate type**, `ScrollbackLog`, not a kind flag on `Region`, and it owns its own buffer + operations (design review: it must not be an anemic holder whose draining lives in `InlineScreen`). The round-3 design review sharpened the interface on three points — make single-writer *structural*, keep the log width-agnostic, and don't leak the batch policy:

```nim
type
  Region* = ref object             # pinned, diff-cached — unchanged
    row*, col*, height*, width*: int
    target: seq[string]            # PRIVATE after S0 slice 2 (see migration note there)
    pending*: bool
    pendingScroll*: int

  ScrollbackLog = ref object       # append-only, never diff-cached — PRIVATE to fresco
    pending: seq[string]           # buffered since last takeBatch

  LogSink* = object                # capability view: enqueue-only, the ONLY surface bindings touch
    log: ScrollbackLog

proc append*(s: LogSink, line: string)                     # sanitize (see below) + enqueue — the sole public door
proc takeBatch(log: ScrollbackLog, max: int): seq[string]  # pipeline-only: hand off ≤max lines, clearing them atomically
proc pendingLen(log: ScrollbackLog): int                   # pipeline-only: buffered count (trigger + drain assertion)
```

**Single-writer is now a type, not a prose invariant (round-3 design CRITICAL).** Round 2 specified single-writer as a discipline the implementer upholds by hand — the same "load-bearing convention" smell this RFC condemns in `invalidate()`. fresco's compile-time-first non-negotiable says defend it with the type system, exactly as `target.nim`'s `ScrollableRenderTarget` concept gates `scrollUp`. So `ScrollbackLog` is **private**; the only handle a binding receives is a `LogSink`, which exposes **`append` and nothing else** — no `takeBatch`, no `flush`, no `pending` access. A `bindScrollback` effect *cannot* flush or write a Region because those symbols are not in its reach; the invariant is the *absence of the symbol*, discharged at compile time, not asserted in a comment. The pipeline (inside `InlineScreen`) holds the real `ScrollbackLog` and is the sole caller of `takeBatch`.

**`takeBatch` replaces `flush():int`; `pendingLen` moves off the public surface (round-3 design HIGH ×2).** The round-2 `flush(log, sink): int` smeared two responsibilities — draining bytes *and* reporting physical rows for cursor accounting — and forced the width-agnostic log to either know `width` or return an ambiguous `int`. And `pendingLen` was *public*, so the batch policy leaked into the interface callers see (feature-envy). The fix: `takeBatch(log, kCommitBatch)` returns up to the watermark of lines and clears them from `pending` in one step, and `pendingLen` survives but only as a **pipeline-private** op on the now-private `ScrollbackLog` (the driver's trigger condition and the drain assertion need a count — a fresco-internal concern, never on the caller-facing `LogSink`). The **pipeline** owns cursor accounting (it calls slice 9's free `physicalRows(lines, width)` on the batch it just took) and owns the batch policy (if `takeBatch` returned exactly `kCommitBatch` lines, there may be more — schedule a `callSoon` continuation). The log stays a pure, width-agnostic buffer: `append` in, `takeBatch` out, `pendingLen` for fresco's own bookkeeping. This also avoids the `flush` vocabulary collision — `TerminalSink.flush` (`terminal.nim:39`) and `Screen.flush` (`screen.nim:114`) both mean "compute pending bytes without emitting," the opposite of "drain to sink"; reusing `flush` for the log would be a coin-flip for any maintainer.

`append` is the **single sanitization chokepoint** — both `appendLine` (imperative) and `bindScrollback` (reactive) route through `LogSink.append`, which sanitizes per the spec below *before* enqueue, so no caller can deposit an unsanitized line and there is exactly one place the rule lives (mirroring how `Region.setRow` is the single clip chokepoint after S0).

`appendLine(screen, line)` is the **sole** imperative door, `= screen.logSink.append(line)` — it **enqueues only**; the actual drain is driven by the commit pipeline (S3 slice 10/11), never by the append call. Because the underlying `ScrollbackLog` is private, there is no `screen.log.append` bypass to compete with it (the round-2 "sugar for `screen.log.append`" framing implied two doors at one layer; the `LogSink` split removes the second). (Round-2 naming retained: the old `commitLine` conflated enqueue with drain and collided with git vocabulary; `appendLine` names the enqueue semantic, matching the imperative `setRow`/`set` family.) Lifecycle: the log is allocated in `newInlineScreen` and owned by the `InlineScreen`; `bindScrollback` captures its `LogSink` scope-bound exactly as `bindRow` captures a `Region`, so disposing the screen's scope tears down the binding — a binding must not outlive the screen, or it appends into a dead log.

Consequences the review demanded: `Layout.regions` stays a homogeneous `seq[Region]` — all pinned — so `render()`'s hot loop never branches on kind. Committed output is a wholly separate code path (the `takeBatch`-driven drain), not a special case inside the diff loop. And **mode is not switchable at runtime**: there is no inline↔alt-screen transition on a live object; you construct one or the other. (A consumer that genuinely needs to toggle constructs a fresh screen and `invalidate`s — documented, not a hot path.)

**Mode lives on the screen type, not on a process-global `Terminal`.** Two screens in one process can have different modes (e.g. amoxtli's REPL inline + a sinopia trace view alt-screen). This is the intended compositional model and resolves where `SurfaceMode` belongs.

## Pinned is clipped; committed is raw (the two width disciplines)

The `Renderer`'s implicit contract is **one logical row = one physical terminal line, and a region owns exactly its rectangle.** This is restored for **pinned** content and deliberately *not* imposed on **committed** content — they have opposite needs:

- **Pinned (live band, alt-screen):** every emitted row is clipped to its region width (escape-aware, by display width, preserving ANSI styling + trailing reset). A row can never bleed past its physical line. *Both modes need this* — in alt-screen a too-long line bleeds horizontally into the next region; same bug class, bounded by the screen instead of scrolling away. This is the shared floor. Vertical: a region paints exactly `height` rows; content shorter blank-fills the remainder; taller is truncated. No stale rows on shrink.
- **Committed (scrollback spill):** emitted **raw**, unclipped, so the terminal's *native* wrap, reflow-on-resize, copy-paste, and history all work on it — the single most portable primitive a terminal has (`print + \n`). Clipping committed content would destroy exactly the native-history behavior that motivates routing it to scrollback. Because committed lines may therefore occupy more than one physical row, the commit pipeline must *measure* their wrapped height for cursor accounting (S3 slice 9).

This split also resolves the depth review's slice-9 contradiction: wrap math is non-trivial precisely because committed content is the *unclipped* path.

## Research / engineering / artifact (the three deliverables)

Per fresco's "research drives engineering" non-negotiable:

- **Theoretical contribution — typed surface ownership as a modality.** Region ownership is a modality over the render surface: `pinned` (`□` — owned, stable, diffable in absolute coordinates) vs `committed` (`◇` — append-only, flushed to a scroll the renderer does not model), borrowing the □/◇ framing from `intonaco/docs/rfc-modal-tiers.md`. The surface mode is encoded as a *type* (`InlineScreen` vs `AltScreen`); the soundness obligation `AltScreen ⇒ committedCount = 0` is discharged **structurally** — the type has no committed-zone field, so the bad state is uninhabited. The contribution is the formalization of the *commit/live boundary* as an ownership type for terminal surfaces — nobody has typed it; Bubble Tea and prompt_toolkit make the split at runtime by convention.
- **Engineering primitives.** Distinct `InlineScreen`/`AltScreen` types (sharing no base and no concept; a `ScreenView` value object where a screen-agnostic API is genuinely needed); a private `ScrollbackLog` exposed only through an enqueue-only `LogSink` capability (`append`) with a pipeline-private `takeBatch` — single-writer discharged structurally, not by convention; width-aware `clipToWidth` (escape-aware truncation) wired through the single `Region.set`/`setRow` chokepoint; the reactive `bindScrollback` + imperative `appendLine` escape, both routing through the single `LogSink.append` sanitization chokepoint; the inline commit as **one public proc `commit*(screen: InlineScreen[S])`** whose body is the otherwise-private pipeline (take-batch/pre-drain-pendingScroll+cursor-to-top → physical-height measurement → emit-committed-via-native-scroll → invalidate-live-band-cache → repaint-live → cursor-home), gated by `commitInProgress` and driven by a `pendingCommit` dirty-flag trigger; alt-screen enter/leave wired to `invalidate` and the async-signal-safe crash-safe exit stack.
- **Research artifact.** Short blog (not a venue paper) in the consistency-model series: *"Typed surface ownership: making the commit/live boundary a compile-time property in a reactive terminal renderer."* Related work to engage explicitly: notcurses's terminal-ownership model, Rust's borrow checker as ownership-as-types, and the □/◇ modal tiers from the consistency model. The novel claim is the *structural* discharge (uninhabited bad state via distinct types) demonstrated by one substrate serving both htop-style and modern-CLI shapes. The discharge is by typing, not Lean — no theorem to mechanize, the type system *is* the proof; this is called out so we do not over-claim a proof obligation that does not exist. **Timing (round-2):** the *type-system* argument (structural discharge) is complete at S4 from the `examples/` alone. The *empirical* "one substrate serving both htop-style and modern-CLI shapes on a real consumer" claim waits for amoxtli's REPL migration — the artifact ships after that migration confirms it, not after S4, so the blog does not over-claim a demonstrated result on aspirational evidence.

## Alternatives considered

- **Two renderers (dedicated inline + dedicated alt-screen).** Rejected: the width-clip, blank-fill, and resize-reflow logic is byte-for-byte identical in both — diverging the implementations doubles the test surface and the bug-fix sites with zero payoff. The only thing that differs between modes is the *top edge of the live zone* and *what happens above it*; that is one parameter, not one renderer each. ink and notcurses/blessed each picked one mode and could not generalize — the consequence of two renderers, observed.
- **DECSTBM-bounded live band (relative coordinates, no absolute tracking).** Viable as an *implementation detail inside* the commit pipeline for a bounded in-band pane, but it does not solve the committed-output-enters-history problem, which fundamentally requires the native-scroll (`print + \n`) path. We keep DECSTBM for bounded in-band scroll (the existing `scrollUpRegion`/`wmFromEnd` path, see below) and use native scroll for history spill. Not a replacement for the absolute-diff core.
- **Synthetic scrollback (fresco models history itself).** Rejected for the inline case: it conflicts with fresco's identity as a library that renders to stderr and does *not* own the full screen inline; it forfeits native copy-paste/reflow and re-implements, worse, what the terminal already does. (In alt-screen mode there is no native scrollback at all, so an app that wants scroll-back-through-history in alt-screen owns its own buffer — but that is the app's concern, not fresco's surface.)

## `scrollUpRegion` is already live (correcting the draft)

An earlier draft claimed `scrollUpRegion`/DECSTBM is "currently unused." **That is false.** `scrollUpRegion` (defined at `render.nim:59`) is called from `TerminalSink.flush` (`render/sink/terminal.nim:54-55`) for any region with `pendingScroll != 0`, and `bindCollection`'s `wmFromEnd` fast-path sets `pendingScroll` (`reactive/binding.nim`; `render/target.nim`). So DECSTBM is already the live fast-path for *bounded in-band* scroll (log-pane tails). `MemorySink` zeros `pendingScroll` without acting on it (`render/sink/memory.nim:47`) — **intentional by design** per `layout.nim:29-32` (sinks that don't support scroll fall back to the full repaint that follows), *not* a defect to fix. The design consequence: S3's commit pipeline uses the **native-scroll** path for history spill and must **not** clobber the existing `pendingScroll` semantics; DECSTBM stays the in-band-pane mechanism. (See "Single-writer discipline" above for how live-band `pendingScroll` is pre-drained at commit entry.)

## Concurrency: commit is dispatcher-atomic

Screen-v2's `runAutoPaint` loop polls (~33 ms) and calls `paint(s)` independently of the commit pipeline. If an auto-paint tick fires *between* the erase/scroll and the repaint of a commit, it would emit a half-finished live band and poison the diff cache (the bug class this RFC exists to kill). Resolution, stated as an S3 postcondition: **a single commit batch runs to completion within one chronos dispatcher turn — it must not `await` mid-batch.** Because chronos is single-dispatcher and cooperative, a non-yielding batch cannot be interrupted by the auto-paint timer.

**The batching/atomicity tension (round-3 CRITICAL — the bounded-latency fix below undermined the atomicity guarantee above).** The "no `await`" guarantee holds *only* for a fully synchronous pipeline. The `kCommitBatch`/`callSoon` watermark introduced for bounded latency (next subsection) *deliberately yields* between batches — which is exactly an interruption point where `runAutoPaint` can fire against a half-scrolled live band (n₁ committed lines emitted, live band not yet repainted). A synchronous pipeline is dispatcher-atomic for free; a *batched* one is not. The two round-2 fixes are in direct tension, and the resolution is an explicit gate, not the absence of `await`:

- **`commitInProgress` flag.** `InlineScreen` carries a `commitInProgress: bool`, set when the pipeline begins and cleared only when the *final* batch completes (not per batch). `runAutoPaint` (or the InlineScreen paint driver) checks it and **skips `paint(s)` for the entire multi-batch span.** The flag need not be atomic — single dispatcher. This makes the *whole commit* (all batches) atomic *with respect to auto-paint*, while still yielding the dispatcher to input and other timers between batches (latency stays bounded; only auto-paint is suppressed, and it has nothing valid to paint mid-commit anyway).
- **Per-batch invariant restore.** Each `callSoon` continuation re-establishes the batch preconditions at its *own* start — it re-runs the live-band `pendingScroll` pre-drain (below) and re-reads `liveZoneHeight` fresh (a SIGWINCH may have landed in the gap). The pre-drain is the per-batch invariant-restore step, **not** a one-time initialization; an implementer who runs it only in the first batch reopens the DECSTBM-after-native-scroll corruption for every subsequent batch.
- **Deferred `liveZoneHeight` write.** The `liveZoneHeight` signal write (which would fire effects that schedule paints) is **deferred to after the final batch**, not performed mid-commit. Because no deferred-write primitive exists in the current signal model (`screen.nim:235` `s.size.set(...)` fires effects eagerly), S3 must implement the deferral explicitly: the resize path stages the new size and the pipeline applies it via `callSoon` after `commitInProgress` clears, so a resize arriving mid-commit takes effect on the next clean turn, never inside a batch.

**The commit pipeline trigger (round-3 CRITICAL — was unspecified).** Nothing in round 2 said *what calls the pipeline*. `runAutoPaint`'s `anyPending` (`screen.nim:133-136`) checks `Region.pending`/`pendingScroll` only — it is blind to `ScrollbackLog` having buffered committed lines, and to `liveZoneHeight == 0` suppression. Trigger model (S3 slice 10c): `appendLine`/`bindScrollback` set a `pendingCommit: bool` dirty flag on `InlineScreen` and, on the *first* enqueue of an idle log, schedule the pipeline via one `callSoon` (idempotent — the flag prevents a second in-flight schedule). The driver test-and-clears `pendingCommit` and runs the pipeline. The trigger condition is `log.pendingLen > 0`, **not** `anyPending(layout)` — otherwise a commit with zero pinned regions (an InlineScreen with no `newRegion` calls) would buffer committed output forever, since `anyPending` is false with no regions.

**Native-scroll cache coherence (round-3 CRITICAL — the root bug, reborn inside the pipeline).** The `Renderer` cache (`render.nim:18-19`) is global and absolute-row indexed; `render()` skips any row where `r.known[absRow] and r.current[absRow] == line` (`render.nim:51`). Emitting committed lines via native scroll (`print + \n`) physically shifts every screen row up by n **but does not touch the Renderer cache** — unlike `scrollUpRegion`, which carefully mirrors the scroll into `current`/`known` (`render.nim:83-91`). So after the committed emit, the cache still believes the live-band content sits at its pre-scroll absolute rows, and the subsequent repaint's diff *skips them as unchanged* while the physical content has scrolled away — leaving stale rows, the exact failure this RFC exists to kill. Discipline (S3 slice 10): **after the native-scroll committed emit and before the live-band repaint, invalidate the Renderer cache for the live-band rows** (cheap — the owned band is tiny; `invalidate()` of the whole cache is acceptable in inline mode where fresco owns only the band). `Region.row` is **invariant** across a commit — the live band is bottom-anchored, so it is repainted at the same absolute rows; it is the *cache*, not the coordinate, that goes stale. (`Region.row` changes only on resize, slice 12.)

**Single-writer discipline for the live band (round-2 CRITICAL — closes the shared-`Region` two-writer window).** "No `await`" is necessary but not sufficient: `bindScrollback`'s reactive `eachDelta` callback runs inside an effect-flush pass and, if it touched a live-band `Region` directly, could set `pending`/`pendingScroll` on it — the exact dirty-marks `anyPending()` checks — at a moment the commit pipeline owns the cursor. The discipline that closes this:

- `bindScrollback` effects **only enqueue into `ScrollbackLog.pending`**. They never write a `Region`, never set `pendingScroll`, never call `scrollUp` on a live-band region. The log is the sole sink for committed deltas.
- The **only** trigger that flushes the log is the commit pipeline's entry — not an effect, not the auto-paint tick. The pipeline drains `log.pending` as its first act, so committed lines are batched per pipeline run, not raced in per delta.
- Any pre-existing `pendingScroll` on a live-band `Region` (from a `wmFromEnd`/`bindCollection` in-band tail — see the `scrollUpRegion` section) is **flushed and cleared by the pipeline before the cursor-to-top step**, so DECSTBM in-band scroll never fires after the native history scroll has already moved the cursor. The subsequent live-band repaint redraws those rows from the diff cache regardless. **Cursor caveat (round-3 depth CRITICAL):** `scrollUpRegion` emits `setScrollRegion`/`resetScrollRegion`, both of which reposition the cursor to (1,1) by terminal convention (`ansi.nim:60-65`). The pre-drain step therefore leaves the cursor at the home position; the pipeline **must** emit an explicit `cursorTo(live-band-top)` as the *immediately following* bytes, before any committed `print + \n`. Otherwise the committed-line newlines scroll from row 1, pushing live content into history from the top instead of spilling below the band. The pre-drain and the cursor-to-top are not separable steps with arbitrary bytes between them.
- A live-band `Region` whose `height` has been clamped to 0 (terminal-too-small, slice 12) must not accumulate a `pendingScroll`: `scrollUp` is guarded to no-op when `r.height == 0` (slice 12), so a stale scroll request can never survive a zero-height window into the next grow-back.

Net: during the atomic commit window the live-band `Region` objects have exactly one writer — the pipeline. `bindCollection`'s DECSTBM fast-path and `bindScrollback`'s log enqueue are both quiesced or pre-drained at the boundary.

**Bounded latency for large committed batches (round-2 MEDIUM).** Dispatcher-atomic and bounded-latency are orthogonal. A burst of (say) 500 committed lines from a long tool result would, as a single non-yielding write, starve all chronos timers and input for the duration of the write. Policy: the pipeline takes at most a watermark `kCommitBatch` lines per run (`log.takeBatch(kCommitBatch)`); if more remain, it emits one batch (atomically), then re-schedules the remainder via `callSoon` — one cooperative yield *between* batches, never *within* one. Each batch is still atomic (correctness preserved); input and other timers get a scheduling slot between batches (latency bounded). The batch boundary is an ordering-neutral split because committed lines are append-only and never re-addressed. Two mechanics this requires (round-3 depth + feasibility):

- **`commitInProgress` spans all batches.** The flag (see "The batching/atomicity tension" above) is cleared only after the *final* batch — so `runAutoPaint` is suppressed for the whole burst, not re-enabled in each gap. The cost is that auto-paint of *reactive* live-band updates is deferred until the burst drains; acceptable, because the live band is repainted at the tail of every batch anyway and a 500-line burst drains in a handful of dispatcher turns.
- **The `callSoon` continuation is a named trampoline, not a closure.** chronos `callSoon(cb, data)` takes a raw `proc(arg: pointer) {.gcsafe, raises: [].}`, not a Nim closure (`chronos/futures.nim`). The continuation is a top-level `proc commitContinue(arg: pointer) {.gcsafe, raises: [].}` that re-casts `cast[ptr InlineScreen](arg)` and runs the next batch; schedule it with the fork's `userCallback` capture (so the dispatcher context is preserved, per CLAUDE.md "Context across await") rather than bare `callSoon`. The pipeline body stays a plain synchronous `proc` (no `{.async.}`, no nested async proc, no `openArray` capture) to stay clear of the known chronos closure-iter transform crashes. This is stated so the implementer doesn't reach for an `async` continuation and trip the transform.

## Capability gating & fallback

`smAltScreen` on a terminal that ignores `?1049h` (dumb terminal, `TERM=vt100`, a pipe, `tmux` with `alternate-screen off`) is a *silent* failure: the enter sequence vanishes, the renderer paints absolute coordinates over live scrollback, the leave sequence vanishes. That is invisible to the user and corrupts the downstream pipe. Policy:

- `newAltScreen` is **gated on `AltScreenCap`**. If the cap is absent, construction **fails fast** with a clear error. There is **no silent inline fallback** — falling back would break the type-level guarantees and surprise the caller. The caller decides what to do on an alt-screen-incapable terminal.
- DECSTBM absence is benign: the commit pipeline's history-spill path is native `print + \n`, which works everywhere; DECSTBM is only the fast path for bounded in-band panes. No fallback needed there.

**`AltScreenCap` must be defined by *this* RFC, not assumed (round-2 CRITICAL).** Feasibility review found `AltScreenCap` does not exist anywhere in `src/` and is **not** defined in `rfc-terminal-interaction.md` (that RFC carries an `altScreen: bool` field on a not-yet-built `Terminal` type, not a cap token). All of S1's alt-screen slices would dead-end on a missing type. Resolution: **S1 defines a minimal `AltScreenCap` cap token inline** using the existing intonaco `cap` macro (the one exercised in `test_capconcept.nim`) — a one-liner that keeps the compile-time-first discipline (cap concept satisfaction over a runtime bool). The full `rfc-terminal-interaction.md` cap layer absorbs/supersedes it later; this RFC does not block on that unbuilt RFC. This is a new **prerequisite slice 4b** (below), ahead of slice 5.

## Crash-safe restore is async-signal-safe (round-2 CRITICAL)

The alt-screen leave on the signal path (slice 6b) must emit `\x1b[?1049l` from inside a POSIX signal handler. `altScreenLeave()` (`ansi.nim:45`) builds `CSI & "?1049l"` — two Nim `string`s concatenated on the GC heap. **Calling that inside a signal handler violates async-signal-safety** (it can deadlock on the GC lock or corrupt the heap if the signal fires mid-allocation), exactly the failure class the existing termios handler (`termios.nim:89-99`) is careful to avoid ("no alloc" — only `tcSetAttr` + raw `write`). A subprocess test does **not** reliably catch this (heap-in-handler bugs are timing-dependent), so "asserted by running it" is not enough.

Discipline: the leave sequence is a compile-time `const` byte buffer (a `cstring`/`array[char]` literal — the `\x1b[?1049l` bytes are statically known), and the output fd is stored as a plain `cint` in the signal-safe exit stack alongside the `TermiosSnapshot`. The handler calls `discard write(fd, leaveSeq, leaveSeqLen)` directly — `write` is on the POSIX async-signal-safe list; no allocation occurs. Slice 6b is specified against this, not against `altScreenLeave()`.

## Multi-screen composition shares one fd (round-2 HIGH)

The "two screens, different modes, one process" claim (e.g. amoxtli REPL inline + a sinopia trace alt-screen) is real but needs a stated discipline: both screens write the same fd (stderr), the SIGWINCH pipe + handler are process-global singletons, and an interleaved `?1049h`/`?1049l` from one screen relocates the *other* screen's absolute-coordinate diff target. **v0 policy: two screens on one fd require explicit caller serialization** — no overlapping `runAutoPaint`, no concurrent commits; the caller owns sequencing (e.g. suspend the inline screen while the alt-screen view is active). This is a documented caller invariant, not a fresco-enforced protocol; a debug-mode assertion detects concurrent commits to the same fd. An fd-level `ScreenMux` is a deliberate non-goal for v0.

## Teardown contract (round-2 HIGH; three-tier, round-4)

Process exit must not silently drop buffered output. "Best-effort" was the wrong frame: it conflated three exit classes that have *different* recoverable guarantees, and hid a correctness gap (a healthy SIGTERM dropping its tail) behind a hedge. The contract splits by exit class, each given the strongest guarantee its execution context allows — and **fresco owns the wiring** via a `withInlineScreen` lifecycle, not the consumer:

1. **Normal return / exception — complete flush.** `withInlineScreen`'s `finally` calls `teardownFlush` in full normal context: drain all of `ScrollbackLog.pending`, emit it raw, and (where the cursor frame is known) repaint the live band a final time. Nothing dropped. The interactive quit is this tier too: in cbreak mode `ISIG` is off, so Ctrl-C arrives as a *keystroke* (the app reads it, calls `teardownFlush`, returns) — never a signal.

2. **Graceful signal (SIGTERM; SIGINT when `ISIG` is on) — deterministic full flush via self-pipe.** The handler does the **one** async-signal-safe thing — write a byte to a self-pipe (the exact trick `watchResizes` uses for SIGWINCH, `screen.nim:154-161`) — and returns. The chronos dispatcher wakes on its next turn and runs `teardownFlush` **in normal context** (heap drain, write loop, final repaint — all legal), then restores the terminal and re-raises the signal to exit with correct disposition. The tail is **never dropped** on a healthy SIGTERM. *Double-signal escalation:* if a second TERM/INT arrives before the dispatcher drains the pipe (a wedged loop), the handler falls through to tier 3's hard path, so the process still dies cleanly.

3. **Hard crash (SIGSEGV/SIGABRT/SIGBUS) — async-signal-safe bounded flush, then restore.** The heap is potentially torn, so we cannot read `pending` (a `seq[string]`). Instead, a **pre-serialized static tail buffer** (a fixed `array[N, byte]` threadvar, mirrored from `pending` in *healthy* context: `LogSink.append` pushes the line's `… \n` bytes in, a successful commit/drain pops them off the front) holds the un-committed committed-output tail in already-rendered bytes. The crash handler does a single raw `write(fd, addr buf, len)` — no alloc, no heap read — then the alt-screen leave + termios restore (slice 6b) and re-raise. This is the **same trust model as the termios-snapshot restore**: bytes frozen in healthy context, flushed by the handler. Bounded by the buffer size (a burst past capacity drops the *oldest* tail bytes — documented, and correct: a crashing process flushing its most-recent committed output, not unbounded history). The committed tail that already reached scrollback is, as always, safe in the terminal.

- **InlineScreen, mid-commit (round-3 breadth HIGH).** If teardown fires while `commitInProgress` is true (a multi-batch commit interrupted between batches), the cursor is at an *undefined* physical row — batch N's native scroll moved it and batch N+1 never ran. All three tiers therefore **emit the remaining tail raw (`line + "\n"`, cursor-unanchored) + a final `\n` and abandon the structured live-band repaint** — repainting at `Region.row` without the current physical cursor would land the band in the wrong rows. A mid-commit kill may leave a partial live band on screen, cleared by the next full repaint; the committed tail is never lost. (Tier 1/2 in normal context *may* repaint when `commitInProgress` is false and the frame is known; tier 3 never repaints.)
- **AltScreen:** the exit path emits a final `paint` (if dirty) *before* `\x1b[?1049l`, so the last frame reflects into the primary buffer where the terminal supports it; then leave. (AltScreen has no `ScrollbackLog`, so tiers 2/3's tail flush is structurally absent — the two surfaces are mutually exclusive.)
- **Multi-screen (v0):** one armed inline screen per process — the static tail buffer + self-pipe track the single armed surface, matching the existing one-fd caller-serialization invariant (two concurrent screens on one fd require caller serialization regardless).
- A broken fd during any teardown emission drops silently rather than raising during unwind.

## Cursor & input (live-band prompt)

The motivating consumer (amoxtli REPL) has a text prompt *in the live band*. After a commit, the physical cursor must land at the prompt's input point or the user's typing feedback is visually wrong (input itself is never lost — keystrokes queue in the chronos input task across the erase/repaint window). Policy: **the commit pipeline ends by positioning the cursor at the live band's declared input point** (explicit `cursorTo`, or `saveCursor`/`restoreCursor` bracketing). This is S3 slice 10b. Bracketed-paste and IME pre-edit during a commit are out of scope for v0 and noted as follow-ons.

## Degenerate & boundary inputs (required invariants)

- **Terminal height ≤ live-band height:** the live band clamps to terminal height and committed output is suppressed (there is no room to spill). Never raise from `newRegion` here — clamp.
- **Live zone clamps to 0 (from a `setSize` shrink):** when `liveZoneHeight` falls to 0 (`screen.nim`'s `setSize` clamps a region's `height` to 0 when `row >= height`), the commit pipeline becomes a **no-op for both the flush and the live repaint**, and `ScrollbackLog.pending` is **preserved, not dropped** — it flushes when the terminal grows back. Tested in slice 12.
- **Zero committed lines / first commit:** the commit pipeline's no-op-emit path still repaints the live band (the initial paint).
- **`width == 0`:** `clipToWidth(s, 0) == ""` for all `s`. `width == 1` with a wide rune → the wide rune does not fit; pad with one space (see S0 slice 1a). In the **height-measurement** formula (slice 9), `width <= 0 ⇒ each line contributes exactly one row` (no division) — guards the divide-by-zero a 0-width fd (`TIOCGWINSZ` returns 0) would otherwise hit.
- **Committed line — sanitization spec (made precise, round-2 depth).** `append`/`bindScrollback` sanitize before enqueue so one logical committed line scrolls **exactly once** and never undercounts the height formula:
  - **Strip** embedded `\n`, `\r`, and **all C0 control bytes < 0x20 except ESC**: in particular `\t` (HT), `\b` (BS), `\v` (VT), `\f` (FF), `\a` (BEL). (`\t`/`\b` would make `displayWidth` mis-measure physical columns vs. what the terminal renders; tabs are replaced by a single space rather than expanded — documented choice.)
  - **Strip** cursor-movement/positioning CSI and **any OSC that sets persistent terminal state** (e.g. `ESC ] 8 ; ; uri ST` hyperlinks) — or, if an OSC is permitted through, it must be *closed* before the line ends (see slice 1b's OSC rule). Motion/positioning is fresco's exclusive domain.
  - **Preserve** styling SGR (`ESC [ … m`) — committed content keeps its color.

## Migration (S0 is a behavior change, not an API change)

S0 changes the **bytes emitted** even though no signature changes: over-wide rows are now clipped, and shrunk regions now blank-fill. Any test asserting exact `flush()` bytes for over-wide or shrinking content will change. This is intentional and correct. Consumers (incl. amoxtli post-migration) should audit tests that assert raw `flush()` output. A regression test in S0 pins the *new* behavior for the previously-bleeding case.

## Why this keeps — and sharpens — the identity

fresco stops being "the inline renderer" or "a TUI kernel" and becomes *a reactive terminal renderer with a pinned-diff core, configurable for inline or screen-owning surfaces, pure-ANSI, diff-minimal.* "Works everywhere / fast / clean" now spans both the htop-style app and the modern-CLI prompt on the same substrate:

- **Works everywhere** — the bulk inline path is `print + \n`, the most universal terminal primitive; the diff surface shrinks from "whole screen" to a few rows.
- **Fast** — less to diff, less to emit; committed output costs nothing to maintain.
- **Clean** — no wrap-bleed, free native scrollback, native copy-paste and resize-reflow of history.

`invalidate()` survives as a true backstop (alt-screen enter/leave, SIGWINCH) and stops being load-bearing, because the owned surface is tiny and re-emitted cheaply.

## Scope / non-goals

- **Not** an amoxtli change. amoxtli's REPL is the proof-consumer and migrates *after* fresco ships this (separate amoxtli work). fresco ships the substrate + headless tests + examples.
- **Not** a rewrite of the diff cache. The `Renderer` core is correct and stays; it is *scoped*, not replaced.
- **Not** character-level diffing (still a later optimization, per render.nim's v0 contract).
- **Not** correctness while the user has scrolled the viewport up (see open questions). fresco guarantees the live band only when the viewport is at the bottom.
- Multi-region horizontal overlap on one row remains unsupported (render.nim v0 contract unchanged).
- Bracketed-paste / IME pre-edit across a commit: out of v0 scope.

## Stages

Each stage is independently shippable; S0 fixes the live corruption on its own.

- **S0 — Width-aware row invariant (the shared floor).** `displayWidth` correctness fixes (zero-width/combining; SS3/DCS/PM/APC) + escape-aware `clipToWidth` (incl. OSC-close) + the `Region.target` privatization migration + single-chokepoint clip in `set`/`setRow` + clear-on-shrink + a debug width-guard. Fixes the corruption in today's de-facto-inline usage with no signature change.
- **S1 — Surface mode + alt-screen ownership.** `AltScreenCap` token; `AltScreen` type; capability-gated alt-screen enter/leave + invalidate + SIGWINCH; full-screen = own the whole layout (existing diff path). Crash-safe restore (exception + **async-signal-safe** signal paths).
- **S2 — Surface typing.** Distinct `InlineScreen`/`AltScreen` types (no shared concept — `ScreenView` value object where needed); private `ScrollbackLog` behind an enqueue-only `LogSink` capability (single-writer made structural) with pipeline-private `takeBatch`; the `AltScreen ⇒ committedCount = 0` obligation discharged structurally + an in-language `compiles()` test with a positive witness.
- **S3 — Inline commit/live engine.** Live-zone physical-height measurement (committed = raw/wrapped, integer-`ceilDiv`, `max(1,…)`); the commit as one `commit*` proc — dispatcher-atomic, single-writer, batch-bounded, `commitInProgress`-gated, dirty-flag-triggered (take-batch + pre-drain pendingScroll+cursor-to-top → emit committed via native scroll → **invalidate live-band cache** → repaint live → cursor-home); reactive `bindScrollback` + imperative `appendLine` over `LogSink`; inline `setSize` reflow (width *and* height, incl. zero-height clamp + `scrollUp` guard).
- **S4 — Proof + examples.** Headless `TerminalSink.flush`/MemorySink end-to-end for both modes; **PTY tier-2 committed-scrollback test**; `examples/` inline-prompt and alt-screen demos (tier-3 manual smoke — visual confirmation of committed scrollback).
- **S5 — Complete teardown (round-4).** Three-tier teardown owned by fresco: SIGSEGV pre-serialized static tail buffer (async-signal-safe raw flush), SIGTERM/INT self-pipe → dispatcher → full `teardownFlush` with double-signal escalation, and a `withInlineScreen` lifecycle guaranteeing the flush on every exit path. Replaces the round-2 "best-effort / drops the tail" hedge.

### S0 — Width-aware row invariant

0a. **`displayWidth` zero-width handling.** Add an `isZeroWidth(r)` check (combining marks U+0300–U+036F etc., ZWJ/ZWSP/ZWNBSP, variation selectors) returning 0 in `displayWidth` (`ansi.nim:127`; the current `else` branch at `ansi.nim:159-161` counts every non-control rune ≥ 1, so these are presently over-counted). **Behavior change:** existing `displayWidth` tests in `test_ansi.nim` that pass combining/ZWJ/variation-selector strings will change value — update them within this slice. Unit tests: accented Latin via combiner, ZWJ, variation selector.
0b. **`displayWidth` extended-escape handling.** Handle SS2/SS3 (`ESC N`/`ESC O`) and string commands DCS/PM/APC (`ESC P`/`ESC ^`/`ESC _` … terminated by `ST`/`BEL`) — all count 0. **Precision:** the current `else` branch skips only the byte after ESC (the designator); SS2/SS3 introduce a *further* single character, so the implementer must `inc i` **twice past the ESC** (designator + introduced byte), not once. Unit tests for each (esp. a DCS payload counting 0, not its byte length; an `ESC N x` counting 0 for all three bytes).
1a. **`clipToWidth(s, width)` — escape-aware width truncation.** Pure fn: truncate to `width` *display* columns via `displayWidth`, passing ANSI escapes through uncounted. Wide-rune half-boundary: if the next rune's width would exceed `width`, **pad with one space and stop** (never emit a partial wide glyph). `width == 0 ⇒ ""`. Unit tests: plain, wide chars, escape passthrough, no-op when ≤ width, wide-char-at-boundary pads, width 0/1.
1b. **`clipToWidth` reset-on-cut + state-leaving escapes.** If *any* SGR escape was seen before the cut (conservative — a reset of default attributes is harmless and avoids an SGR state machine), append `\x1b[0m`. **OSC (round-2 depth):** an SGR `\x1b[0m` does **not** close an OSC hyperlink (`ESC ] 8 ; ; uri ST`); a cut mid-link-text leaves the terminal's hyperlink state contaminated for all later output. Cursor-movement/positioning escapes in row content remain forbidden (fresco owns all cursor moves). Unit tests: styled cut appends reset; `\x1b[1m\x1b[22m…` still appends (conservative, documented); an OSC-hyperlink cut either rejected (pinned) or closed with `ST` (committed).
1c. **`clipToWidth` property suite (proptest).** `displayWidth(clipToWidth(s,w)) ≤ w` for all `s`,`w≥0`; idempotence `clipToWidth(clipToWidth(s,w),w) == clipToWidth(s,w)`; output contains no split CSI/OSC and no OSC left open. No behavior change — pure seam. (Feasibility flagged this hidden migration; it must land before 2b or 2b won't compile.)

A too-long row emits clipped bytes — no physical-line bleed. ### S2 — Surface typing

7. **Distinct `InlineScreen`/`AltScreen` types (no shared concept) + private `ScrollbackLog` with an enqueue-only `LogSink` capability.** `ScrollbackLog` is private (`append`-via-`LogSink`, pipeline-private `takeBatch`); `InlineScreen` exposes a `LogSink` (the only handle bindings get) and holds the real log + `pendingCommit`/`commitInProgress` flags. Caller-owned `size: Signal[(int,int)]` constructor (+ static `(h,w)` convenience); `liveZoneHeight = size.map(…)`. Default pinned-region behavior byte-identical to today (regression test: existing render bytes unchanged). `Layout.regions` stays homogeneous pinned. `ScreenView` value object defined for any screen-agnostic API. Test the capability split: `LogSink` exposes `append`; `compiles(logSink.append("x"))` holds and `compiles(logSink.takeBatch(1))` does not (single-writer is structural).
8. **`AltScreen ⇒ committedCount = 0` discharged structurally.** `AltScreen` has no `ScrollbackLog` field and no `appendLine`/`bindScrollback` proc, so `appendLine(altScreen, …)` is a *compile error*. **Test it soundly with the in-language `compiles()` builtin** — fresco already uses `check not compiles(…)` for exactly this (`test_capconcept.nim:47,69,…`); no `nim check` subprocess, no `negativeCompile` helper (both false-pass on the *wrong* compile error — a typo, a missing import). Soundness guard against the vacuous-pass trap: the **same test** first establishes the **positive witness** — `check compiles(appendLine(inlineScreen, "x"))` must hold (proving `appendLine` exists and is callable) — *then* `check not compiles(appendLine(altScreen, "x"))`. If the negative failed for a typo, the positive would catch it. (Soundness conditions on mode *transitions* are vacuous here: modes are distinct types constructed fresh, not toggled — documented in S2.)

### S3 — Inline commit/live engine

9. **Live-zone physical-height measurement.** Pure free function `physicalRows(line: string, width: int): int` (free-standing — no dependency on slice 7, can land first): committed content is **raw/unclipped**, so physical height per line = `max(1, ceilDiv(displayWidth(line), width))`. **Integer-ceiling precision (round-3 depth + feasibility — both flagged):** write the ceiling as integer `(dw + width - 1) div width` (or `ceilDiv`), **never** truncating `dw div width` (floor — undercounts every non-multiple width, the silent trap in an "obvious" formula) and never float `math.ceil` (needless float round-trip). `dw = max(0, displayWidth(line))`. The `max(1, …)` is load-bearing (round-2 CRITICAL): a printed line *always* advances one physical row even when its `displayWidth` is 0 (pure-SGR line, OSC-only line, empty string); plain `ceilDiv(0, width) = 0` would place the cursor one row too high per such line and corrupt the diff cache. Guard `width <= 0 ⇒ one row per line` (short-circuit *before* the division — a 0-width fd from `TIOCGWINSZ` would divide-by-zero otherwise). Unit tests across wrap boundaries (exact-width → 1 row, width+1 → 2 rows, multi-row) **and** a pure-SGR line measuring to 1 **and** a non-multiple width (e.g. dw=5, width=3 → 2, proving it's ceil not floor).
10. **Commit pipeline primitive (dispatcher-atomic, single-writer) — `proc commit*(screen: InlineScreen[S])`.** The pipeline is **one public proc** (round-3 design: name the module boundary; the steps below are its private body, not a recipe the caller sequences). Preconditions: called from a dispatcher turn, not mid-`await`. Postcondition: cursor at the live band's input point; `pending` empty or a `callSoon` continuation scheduled. Body, in exact order:
    1. `takeBatch(log, kCommitBatch)` — pull up to the watermark, clearing them atomically; if it returned exactly `kCommitBatch`, a continuation is scheduled at the end (see bounded-latency).
    2. Pre-drain + clear any `pendingScroll` on live-band Regions (so DECSTBM can't fire post-native-scroll), then **immediately** emit `cursorTo(live-band top)` — the pre-drain's `scrollUpRegion` left the cursor at (1,1) (round-3 depth CRITICAL-2), so the cursor-to-top must be the very next bytes, before any committed print.
    3. Measure the batch's physical height via `physicalRows` (slice 9) for cursor accounting.
    4. Print committed lines + `\n` (natural scroll into history, DECSTBM unset). **No erase-first step** (erasing first would scroll *blanks* into history; the repaint covers the old rows).
    5. **Invalidate the Renderer cache for the live-band rows (round-3 depth CRITICAL-1).** Native scroll physically moved the band up by the batch's measured height but did not touch the cache (`render.nim:51,83-91`); without this the repaint's diff skips the now-stale rows. `Region.row` is **unchanged** — the band is bottom-anchored.
    6. Repaint live band at its (unchanged) `Region.row`.
    7. Cursor → input point (slice 10b).

    Runs without `await` mid-batch; `commitInProgress` is held across all batches and gates `runAutoPaint` (see Concurrency). Debug assertions (`when compileOption("assertions")`, round-3 breadth — analogous to slice 4's width guard): after the final batch, `log.pendingLen == 0` and `not anyPending(layout)` — catches a pipeline that returned early without draining or repainting. Depends on slice 7 (`InlineScreen`/`ScrollbackLog`).

    **Testable byte-capture seam (round-3 feasibility CRITICAL).** `TerminalSink.flush` (`terminal.nim:39`) takes only a `Layout` and iterates `layout.regions` — it has **no path** for committed lines emitted by raw `write`, so the round-2 "byte-order test via `TerminalSink.flush`" has no mechanism. Resolution: `commit*` builds its full output as a single byte string (committed lines → cursor moves → repaint diff) and emits it through one `write`; expose that string to the test (the pipeline computes-then-emits, mirroring `flush`'s compute-then-`commit` split). MemorySink models no scrollback (slice 13), so committed bytes are **only** assertable through this seam, not MemorySink. **Test population:** drive `LogSink.append` (via `appendLine`, the public door) directly to pre-fill `pending` — slice 10 does **not** depend on slice 11's `bindScrollback` to get lines into the log. Byte-order test: committed lines → cursor-to-top → live-band repaint, in order; plus a pure-SGR committed line advancing exactly one row.
10b. **Cursor-home after commit.** Pipeline ends with the cursor at the live band's declared input point. Byte test asserts the final `cursorTo` targets the input row/col.
10c. **Pipeline trigger + `commitInProgress` gate (round-3 breadth/depth CRITICAL).** Specify *what drives* `commit*`: `LogSink.append` (reached by `appendLine`/`bindScrollback`) sets `InlineScreen.pendingCommit`; on the first enqueue into an idle log it schedules `commit*` via one idempotent `callSoon` (the flag prevents a second in-flight schedule). The driver test-and-clears `pendingCommit`. Trigger condition is `log.pendingLen > 0`, **not** `anyPending(layout)` — else an `InlineScreen` with zero pinned regions buffers committed output forever. Add `commitInProgress: bool` set on `commit*` entry, cleared after the final batch; the paint driver skips `paint(s)` while it is set. Tests: (a) one `appendLine` schedules exactly one pipeline run (no double-schedule on a second append before the first drains); (b) a zero-region InlineScreen still flushes committed output; (c) a synthetic auto-paint tick during a (forced multi-batch) commit is suppressed — no torn output.
11. **`bindScrollback` (reactive) + `appendLine` (escape) over `LogSink`.** `bindScrollback(logSink, collectionSignal, fmt = $T)` routes overflow (items beyond `liveZoneHeight`) into the log **through the enqueue-only `LogSink`** — it has no `takeBatch`/Region access, so single-writer is structural, not promised. `appendLine(screen, line)` is the one-shot imperative enqueue (banners/prompt), `= screen.logSink.append(line)` — the sole imperative door (the private `ScrollbackLog` has no competing public `append`). Sanitization lives in **`LogSink.append` alone** (the single chokepoint — strip `\n`/`\r`/C0-controls/motion-CSI/state-OSC, keep SGR), so neither caller can deposit an unsanitized line and the rule has exactly one home. **Ordering invariant (round-3 breadth):** within one dispatcher turn, non-effect `appendLine` calls enqueue before the next effect-flush; `bindScrollback`'s appends occur during effect-flush. Calling `appendLine` from *inside* an effect (directly or transitively) has undefined order relative to other effects in the same flush — documented as a caller bug, no v0 runtime enforcement. Depends on slice 7 + slice 10. Test: a second append does not re-emit the first (idempotency via absence in subsequent commit bytes); a `bindScrollback` effect body cannot reach `takeBatch` (compile-level — the symbol isn't on `LogSink`).
12. **Inline resize reflow (width *and* height) — `setSize(s: InlineScreen, h, w)` is real new code.** Round-2 claimed this "relies on the existing `setSize → invalidate` path in `screen.nim` — already present." **That is false (round-3 feasibility CRITICAL):** `setSize` lives at `screen.nim:210` on `Screen[S]`, a *distinct* type; `InlineScreen` shares no base and has none. This slice **implements** `setSize(s: InlineScreen, h, w)`: (1) update `layout` width/height, (2) recompute `liveZoneHeight` from new `h` + the baked `pinnedHeaderRows`, (3) `renderer.invalidate()`, (4) clamp/truncate live-band regions exactly as `screen.nim:222-233` does (but do **not** copy its `setLen`-without-clip latent bug — clip via S0's `clipToWidth`), (5) mark regions pending, (6) stage `size` (deferred-write discipline — applied after any in-flight `commitInProgress` clears, never mid-batch). Committed history is the terminal's responsibility. **Zero-height clamp:** when the new `liveZoneHeight` is 0, the pipeline no-ops both drain and repaint and **preserves `pending`** (re-drains on grow-back); additionally guard `scrollUp` to no-op when `r.height == 0` (round-3 breadth — else a `wmFromEnd` delta during a zero-height window leaves a stale `pendingScroll` that fires wrongly on grow-back). **Resize between batches (round-3 depth/breadth):** a SIGWINCH landing in a `callSoon` gap means the next batch must re-read `liveZoneHeight` at execution time, not a value captured at schedule time. Tests: width-change band integrity; **height-shrink** repaint at new rows; **zero-height** preserves pending + no-op + `scrollUp` leaves `pendingScroll == 0`; **synthetic SIGWINCH between two commit batches** yields a clean band, not a torn one; none re-emit committed lines.

### S5 — Complete teardown contract (round-4: replace the "best-effort" hedge with the three-tier design above)

These implement the rewritten **Teardown contract** section. The slice-13b "synthetic SIGTERM flushes the tail" assertion was the canary that exposed the gap — slice 15 makes it real, not a documented limitation.

15. **SIGSEGV/ABRT/BUS tier — pre-serialized static tail buffer + crash-handler flush.** A fixed `array[N, byte]` threadvar (`sigTailBuf`) + `sigTailLen`/`sigTailFd`/`sigTailActive` `cint` flags (mirroring slice 6b's `sigAltScreen*`). Maintained in **healthy context**: `LogSink.append` appends the sanitized line's `… "\n"` bytes; a successful `commit`/drain pops the emitted prefix (memmove the remainder down). On overflow, drop the *oldest* bytes (bounded — a crash flushes recent committed output, not unbounded history). Wire a single async-signal-safe `posix.write(sigTailFd, addr sigTailBuf, sigTailLen)` into the fatal-signal handler (`termios.nim`), gated by `sigTailActive`, **before** the termios restore. `armInlineTailBuffer(s, fd)` / `disarmInlineTailBuffer()`. Tests: unit — `sigTailBuf` byte-mirrors `pending` across append/commit cycles incl. overflow-drops-oldest; **tier-2** — a `runInPty` subprocess (the slice-6b harness, finally consumed) buffers lines then raises SIGSEGV; assert the master stream contains the buffered tail + a restored terminal. Async-signal-safety verified by inspection (const-size buffer, raw write, zero alloc in handler).
16. **SIGTERM/INT graceful tier — self-pipe → dispatcher → full `teardownFlush` + double-signal escalation.** A self-pipe (mirror `screen.nim`'s `winchPipe`/`watchResizes`). First TERM/INT: handler sets `sigGracefulPending`, writes one byte, returns (no die). A chronos `watchTeardownSignals(s)` task (spawned by the lifecycle, parallel to `watchResizes`) wakes on the pipe, runs `teardownFlush` in normal context (full drain + emit + repaint-if-frame-known), restores the terminal, and re-raises to exit. Second TERM/INT before the dispatcher drains the pipe → handler falls through to slice 15's hard path (wedged-loop backstop). Tests: **tier-2** `runInPty` — child installs the lifecycle, buffers a partial commit, parent sends SIGTERM; assert full tail flushed + clean exit + terminal restored; a second test sends two rapid SIGTERMs and asserts the escalation still exits cleanly.
17. **`withInlineScreen` lifecycle — fresco owns the wiring.** Template mirroring `withCbreak`/`withAltScreen`: construct the screen, `armInlineTailBuffer` + install the graceful handlers + spawn `watchTeardownSignals`, `try: body finally: teardownFlush(s); disarm…`. Guarantees the flush on **every** exit path — return, exception, signal — with zero consumer plumbing. Tests: normal return flushes (tier-1); an exception in the body still flushes then re-raises; arm/disarm pairs correctly under nesting (mirror `installSignalHandlers`' bounded stack). The signal paths are covered by 15/16; this slice proves the return/exception guarantees + the ownership ergonomics.

## Open questions (for architecture review)

- **Viewport scroll during live-band paint.** When the user scrolls the terminal viewport up (mouse wheel) while the live band repaints, absolute `cursorTo` addresses the scrolled viewport, not the physical bottom — the same coordinate-frame bug, now in the live band. v0 stance (in Scope/non-goals): fresco guarantees the live band only at the bottom of scrollback. **Open:** is that stance acceptable for v0, or should fresco detect scroll mode (via the `?1006`/`?1015` mouse protocol) and suspend auto-paint while scrolled? Lean: ship the v0 stance, file scroll-suspend as a follow-on.
- **`bindScrollback` vs `appendLine` as the primary API.** This RFC makes the reactive `bindScrollback` primary and `appendLine` the imperative escape, mirroring `bindCollection`. `bindScrollback`'s `fmt` defaults to `$T` (matching `bindCollection`, not the gratuitously-mandatory form an earlier draft had). Composability with screen-v2's frame-clock holds via the single-writer discipline (effects enqueue into the log; only the pipeline flushes). **Resolved follow-on (not a v0 blocker):** extend the `region()` DSL with a `scrollback(log):` arm so committed and pinned content wire up visually parallel; filed as a post-S4 ergonomic slice, not required for the engine to ship.
- **`ScreenLike` concept — RESOLVED (dropped).** Round 2 found the concept was a phantom: `bindRow`/`bindRows`/`region` take a `Region`, `bindCollection` takes a `RenderTarget` — none reach for a screen member, so there was nothing to abstract, and Nim concepts imported opaque-error fragility for no payoff. Any genuinely screen-agnostic API takes the explicit `ScreenView` value object (`layout` + `size`) instead. No open question remains.
